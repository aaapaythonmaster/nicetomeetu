# 个人简历网站设计规格

日期：2026-08-17

状态：设计已逐节确认，等待书面规格最终审阅

目标仓库：`aaapaythonmaster/nicetomeetu`

## 1. 项目目标

建设一个面向招聘公司的桌面端个人简历网站。网站以 Word 简历为内容来源，提供产品经理版与产品运营版两个独立简历槽位。站点管理员可以在线上传固定结构的 Word 简历，校对解析结果，调整展示内容和视觉参数，预览后发布其中一个版本。招聘方只能看到当前公开版本，不能切换求职方向。

本次 Demo 必须实现完整闭环：管理员登录、上传 Word、规则解析、校对、预览、发布、公开浏览和下载 PDF 均可实际使用，并部署到 Vercel。

## 2. 范围与非目标

### 2.1 本期范围

- 桌面端公开个人主页与四个独立详情页。
- 两级 React Bits `OptionWheel` 交互。
- `ColorBends` 与 `DotField` 双层动态背景。
- 单管理员邮箱密码登录。
- 产品经理版、产品运营版分别上传和维护。
- 固定 Word 结构的本地规则解析，不调用外部 AI。
- 草稿校对、排序、隐藏、重复提示、预览和发布。
- 视觉参数草稿、实时预览、恢复默认和发布。
- 根据结构化数据生成可下载 PDF。
- Supabase Auth、Postgres 与 Storage。
- GitHub 到 Vercel 的部署流程。

### 2.2 明确不做

- 不支持手机和平板响应式布局。
- 不向招聘方提供简历版本切换入口。
- 不提供公开注册或多管理员协作。
- 不使用 AI 解析、改写或总结简历。
- 不把网站编辑结果写回原始 Word。
- 不复刻原 Word 的 PDF 排版。
- 不保留多次历史发布记录；每个槽位只有一个线上版本和一个草稿。
- 不提供 Option Wheel 音效。
- 不提供访客关闭动效或自动低性能降级开关。
- 不引入 Railway、Render 或第二套后端服务。

## 3. 用户与权限

### 3.1 招聘方

- 无需登录。
- 只能读取当前公开简历版本和已发布视觉参数。
- 可以浏览首页、四个详情页并下载当前公开版本 PDF。
- 无法读取草稿、原始 Word、隐藏手机号或后台接口。

### 3.2 管理员

- 使用预先创建的唯一管理员邮箱和密码登录。
- 后台不提供注册入口。
- 可以上传、校对、预览和发布两个简历版本。
- 可以选择唯一公开版本。
- 可以修改视觉参数并单独预览、发布。

管理员授权以 Supabase `auth.uid()` 和管理员白名单表为准，不使用用户可编辑的 metadata 做权限判断。

## 4. 公开网站信息架构

### 4.1 路由

- `/`：公开首页。
- `/internships`：实习经历详情。
- `/projects`：项目经历详情。
- `/campus`：校园经历详情。
- `/skills`：技能详情。
- `/admin/login`：管理员登录。
- `/admin`：后台首页。
- `/admin/resumes/[profile]`：指定简历槽位的上传与校对。
- `/admin/preview/[profile]`：指定简历草稿的完整预览。
- `/admin/appearance`：视觉设置。
- `/admin/appearance/preview`：视觉草稿预览。

`profile` 只允许 `product-manager` 或 `product-operations`。

### 4.2 首页

顶部展示：

- 姓名。
- 当前公开求职方向。
- 学校。
- 公开邮箱。
- 手机号；默认隐藏，管理员可按版本开启。
- “下载 PDF 简历”入口。

主体采用左右分栏：

- 左侧展示当前一级栏目的短简介、代表数据和详情入口。
- 右侧使用一级 `OptionWheel`，选项固定为“实习经历、项目经历、校园经历、技能”。
- 首次打开默认选中“实习经历”。
- 滚轮停稳后通过 `onChange` 更新左侧内容。
- 点击左侧简介区域进入对应独立详情页。

### 4.3 详情页

四个详情页共用页面基座、顶部身份信息和返回首页入口。主体仍为左右分栏：

- 左侧展示当前二级条目的完整结构化内容。
- 右侧使用二级 `OptionWheel` 切换条目。

二级滚轮规则：

- 实习经历：按岗位短标题切换，例如“AI 产品经理、AI 应用、AI 业务提效、数据运营、数据资产”；公司名称、时间、职责和成果显示在左侧。
- 项目经历：按项目短标题切换。
- 校园经历：按组织或经历短标题切换。
- 技能：按技能类别切换。

滚轮短标题可在后台修改，以避免过长文字破坏弧形布局。

## 5. Option Wheel 交互规范

组件基于用户提供的 React Bits `OptionWheel` JavaScript + CSS 版本。必须保留真实组件行为，不能替换为普通静态列表：

- 选项沿弧线排布。
- 中央选中项提高字重并使用活动颜色。
- 远离中央的选项逐步旋转、模糊和淡出。
- 支持鼠标滚轮、触控板、拖拽、直接点击和方向键。
- 滚动结束后吸附到完整选项。
- `loop` 默认关闭。
- `draggable` 开启。
- 音效关闭且本期不提供音效设置。
- 组件保留 `role=listbox`、`role=option`、`aria-selected` 和键盘焦点。

后台可编辑的高级参数包括 `fontSize`、`spacing`、`curve`、`tilt`、`blur`、`fade`、`minOpacity`、`smoothing` 和 `inset`。

## 6. 视觉系统与动态背景

整体高度还原 React Bits 首页的深色紫黑视觉、排版节奏和动效氛围，但使用张昕蕊的个人身份、简历结构和统一品牌语言，不做机械式像素复制。

首页背景由两个独立图层叠加：

1. `ColorBends`：WebGL 流动色带层。
2. `DotField`：Canvas 鼠标响应点阵层。

两个动效共用全局主色，默认值为 `#06b6d4`。主色变化时：

- `ColorBends.colors` 使用主色。
- `DotField` 从主色自动生成同色相的浅色与深色渐变。
- Option Wheel 活动色、按钮、链接和焦点状态联动更新。
- 高级设置允许覆盖衍生色，但默认保持统一。

默认衍生规则固定为：浅色等于主色与白色按 70%/30% 混合，深色等于主色与背景色 `#120f17` 按 72%/28% 混合。后台修改主色后立即按该规则重新计算；只有管理员主动启用高级颜色覆盖时，才保存独立衍生色。

### 6.1 ColorBends 默认值

| 参数 | 默认值 |
| --- | ---: |
| colors | `[#06b6d4]` |
| rotation | 60 |
| autoRotate | 0 |
| speed | 0.2 |
| scale | 1 |
| frequency | 1 |
| warpStrength | 1 |
| mouseInfluence | 1 |
| parallax | 0.5 |
| noise | 0.15 |
| iterations | 1 |
| intensity | 1.3 |
| bandWidth | 1 |
| transparent | true |

### 6.2 DotField 默认值

| 参数 | 默认值 |
| --- | ---: |
| dotRadius | 1.5 |
| dotSpacing | 14 |
| cursorRadius | 500 |
| cursorForce | 0.1 |
| bulgeOnly | true |
| bulgeStrength | 67 |
| glowRadius | 160 |
| sparkle | false |
| waveAmplitude | 0 |
| gradientFrom | 主色浅色衍生值 |
| gradientTo | 主色深色衍生值 |

公开站点始终展示完整动效，不根据设备性能或 `prefers-reduced-motion` 主动降级。实现必须隔离背景层：任一动效加载失败时，正文、导航和滚轮仍保持可用。

## 7. Word 上传与解析

### 7.1 输入约束

- 只接受 `.docx`。
- 验证扩展名、MIME、文件大小和压缩包结构。
- 原始 Word 保存到 Supabase 私有 Storage，不进入 Git 仓库。
- 产品经理版和产品运营版分别上传。

### 7.2 规则解析

解析器按固定栏目标题和段落层级提取：

- 基本信息。
- 教育背景。
- 实习经历。
- AI 项目实践或作品集。
- 技能。
- 自我评价。
- 校园经历。

解析器不得调用外部 AI。格式异常时生成结构化问题列表，不猜测内容。

### 7.3 校验与重复检测

- 检查必需栏目是否缺失。
- 检查日期格式和时间区间。
- 检查无法归类的段落。
- 对标题和正文高度相似的条目标记“疑似重复”。
- 重复项不自动删除，由管理员在校对页处理。

当前 Demo 简历中重复的项目一与项目二应触发该提示。

### 7.4 栏目简介

首页四个栏目需要短简介。系统以确定性规则生成基础摘要草稿，例如栏目计数、第一段有效描述和已识别量化指标；管理员必须在预览后台精简确认。不得调用 AI，也不得直接截断导致半句话。

## 8. 后台校对与发布

解析完成后进入草稿校对页。管理员可以：

- 修改解析文字。
- 修改栏目简介。
- 修改二级滚轮短标题。
- 拖拽排序。
- 隐藏单个条目。
- 处理疑似重复项。
- 设置手机号是否公开。

这些修改只写入网站草稿，不修改原始 Word。

发布前必须完整预览：

- 首页四个一级栏目状态。
- 四个详情页及二级滚轮。
- 公开个人信息。
- 下载版 PDF。
- 已发布视觉参数或视觉草稿组合。

产品经理版与产品运营版各自最多保存：

- 一个已发布 revision。
- 一个未发布 draft。

全站同时只有一个 `active_profile`。发布和切换公开版本必须原子完成，失败时不得修改现有线上状态。

## 9. PDF 下载

- PDF 根据当前已发布的结构化数据生成。
- PDF 顺序与公开网站中的已发布顺序一致。
- 隐藏条目和隐藏手机号不得出现在 PDF。
- PDF 采用适合打印和投递的简洁排版，不复刻 React Bits 动效，也不要求复刻原 Word 版式。
- 只有生成成功的 PDF 才能随简历发布。
- 公开下载统一通过 Next.js `/api/resume/pdf` 接口提供。接口只解析当前已发布 revision 对应的 PDF，不接受任意 Storage 路径；原始 Word 永不公开。

## 10. 技术架构

### 10.1 应用

- Next.js App Router。
- TypeScript。
- 单一 GitHub 仓库。
- 前端页面、管理后台和服务端接口处于同一 Next.js 项目。
- 默认使用 Node.js runtime 处理 Word 与 PDF；交互动画位于客户端组件边界内。

### 10.2 部署

- GitHub 仓库：`aaapaythonmaster/nicetomeetu`。
- Vercel 托管 Next.js 应用。
- Supabase 提供 Auth、Postgres 和 Storage。
- 不使用 Railway 或 Render。
- 密钥通过 Vercel 环境变量管理。
- `.env`、Word、PDF、数据库导出和视觉辅助目录不得提交。

### 10.3 缓存

公开页面只读取当前已发布快照，并在 Vercel 层缓存。发布成功后主动使对应缓存失效。招聘方正常访问不应每次依赖实时数据库查询；Supabase 暂时不可用时，已有公开缓存应继续提供最后一次成功发布的内容。

## 11. 逻辑数据模型

### 11.1 主要实体

- `admin_users`：允许管理站点的 Supabase 用户 ID。
- `resume_profiles`：两个固定槽位及唯一公开状态。
- `resume_revisions`：草稿或线上 revision、解析状态和发布时间。
- `resume_sections`：栏目类型、简介、顺序和可见性。
- `resume_entries`：条目标题、滚轮短标题、结构化正文、顺序和可见性。
- `resume_files`：Word、PDF 的 Storage 路径、校验信息和状态。
- `parse_issues`：缺失、未识别、重复或日期问题。
- `appearance_settings`：视觉草稿或线上参数。

### 11.2 数据库原则

- 使用明确主键、外键、唯一约束、检查约束和 `timestamptz`。
- 所有外键列建立索引。
- 高频读取的“当前公开”“草稿”“可见顺序”查询建立匹配索引或部分索引。
- 数据库约束确保每个 profile 最多一个线上 revision 和一个 draft。
- 排序使用整数位置，发布前校验重复位置。
- 结构化正文可以使用有版本号的 JSON 字段，但核心状态、关系、顺序和权限字段必须规范化。

## 12. Supabase 安全

- 所有公开 schema 表启用 RLS。
- 匿名角色只允许读取当前公开且可见的数据。
- 已登录用户不能仅凭 `authenticated` 角色获得管理权限，必须同时匹配 `admin_users.user_id = auth.uid()`。
- 管理员 UPDATE 策略同时提供 `USING` 与 `WITH CHECK`。
- RLS 中使用 `(select auth.uid())`，并索引权限判断涉及的列。
- 不使用 `raw_user_meta_data` 或 `user_metadata` 授权。
- 不在客户端暴露 Supabase secret 或 `service_role`。
- 如确需特权发布函数，函数放在非公开 schema，显式校验 `auth.uid()`，限制 `EXECUTE`，固定空 `search_path`，并在上线前运行数据库安全检查。
- Storage 原始文件桶为私有桶；覆盖文件时策略覆盖 INSERT、SELECT 和 UPDATE。

## 13. 错误处理

- 上传失败：保留现有草稿，展示可重试错误。
- 解析失败：保存原文件与解析日志，不生成可发布草稿。
- 校验失败：集中展示问题并阻止发布。
- PDF 失败：保留草稿并阻止发布。
- 发布事务失败：线上版本和公开 profile 保持原值。
- 数据库或 Storage 临时失败：不清空已有表单内容，提供重试。
- 未登录或越权访问：跳转登录或返回明确拒绝状态。
- 公开内容不存在：显示可恢复的站点未发布状态，不暴露后台信息。
- 动效失败：只移除失败背景层，不影响正文与导航。

## 14. 测试与验收

### 14.1 自动化测试

- Word 解析单元测试：当前简历、缺失栏目、重复项目、未知段落和日期变化样本。
- 数据映射测试：首页摘要、条目顺序、隐藏项和滚轮短标题。
- RLS 测试：匿名、普通登录用户和管理员三种身份。
- 发布事务测试：成功发布、PDF 失败、Storage 失败和并发发布。
- PDF 测试：栏目完整、顺序正确、隐私字段正确。
- 组件测试：Option Wheel 选择、拖拽、滚轮、点击、键盘与 `onChange`。

### 14.2 完整流程验收

1. 管理员登录。
2. 选择产品经理版或产品运营版。
3. 上传 Word。
4. 查看解析问题。
5. 修改文字、摘要、顺序、可见性和滚轮短标题。
6. 预览首页、详情页与 PDF。
7. 发布。
8. 选择唯一公开版本。
9. 无痕浏览器访问公开网站。
10. 验证招聘方只能看到公开版本并能下载正确 PDF。

### 14.3 视觉验收

- 在桌面版 Chrome、Edge、Safari 检查 1440px 与 1920px 宽度。
- 检查 `ColorBends` 与 `DotField` 叠加效果和鼠标响应。
- 检查全局主色联动。
- 检查一级、二级 Option Wheel 弧形、模糊、淡出和选中状态。
- 检查控制台无未处理错误。
- 生成预览页时必须调用全局 `impeccable` 技能，审查层级、间距、文字可读性、焦点状态、动效强度和一致性。

## 15. 成功标准

- 空仓库可以在 Vercel 上成功部署。
- Supabase 连接、Auth、RLS、Database 和 Storage 均通过验证。
- 当前提供的“AI 流程运营”Word 能生成可校对草稿，并标出重复项目。
- 不改代码即可通过后台上传同结构的新简历并发布。
- 管理员可以分别维护两个求职版本并决定唯一公开版本。
- 公开页面与详情页完整呈现真实 Option Wheel 交互。
- 两层背景动效采用可发布的参数草稿和统一主色。
- 招聘方无需登录即可稳定浏览和下载 PDF，但无法访问草稿与原始 Word。
- 所有验收流程在桌面端通过。
